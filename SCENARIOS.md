# Сценарии: ограниченные методы чатов

1. В `VK Teams` выбрать `Chat` → `Create Chat`, указать `Name` и оставить остальные значения по умолчанию. Результат: один `GET /chats/createChat` без `chatId` и `members`, с `public=false`, `joinModeration=false`, `defaultRole=member`; ответ содержит `sn` нового чата, если сервер разрешает метод.
2. При создании чата указать двух участников строковыми ID и заполнить описание, правила, видимость и модерацию. Результат: один запрос с `members=[{"sn":"…"},…]` и выбранными параметрами; введённые ID не превращаются в числа и не меняют токен.
3. В `Chat` → `Add Members` передать `Chat ID` и непустой массив строковых ID. Результат: один `GET /chats/members/add`; если сервер вернул документированный частичный результат с `failures` (включая `ok=false` без общей ошибки), он сохранён в JSON для последующей обработки workflow.
4. Передать пустой список, повторные, числовые или повреждённые ID в `Add Members`, либо пустое имя в `Create Chat`. Результат: понятная ошибка до HTTP-запроса; существующий чат не меняется.
5. На сервере без метода или без прав бота выполнить любую из двух операций. Результат: ошибка сервера остаётся ошибкой ноды или попадает в `Continue On Fail` своего item; нет обходного endpoint и автоматического повтора.
